# شرکت خمیر مایه خوزستان — وب‌سایت چندصفحه‌ای ری‌اکت

> **از مغز گندم؛ تا اولین برش نان**
> From the heart of wheat; to the first slice of bread

بازطراحی کامل وب‌سایت شرکت خمیر مایه خوزستان (khuzestanyeast-co.com) به‌صورت یک وب‌اپلیکیشن
چندصفحه‌ای مدرن با React، با هویت بصری **قرمز لاکی (Crimson) و سفید**، کاملاً راست‌چین (RTL) و
سرشار از انیمیشن‌های حرفه‌ای.

> 🚀 **می‌خواهید سایت را روی هاست بالا بیاورید؟**
> به بخش **«راه‌اندازی روی cPanel — راهنمای گام‌به‌گام»** در پایین همین صفحه بروید.

## ✨ ویژگی‌ها

- **چندصفحه‌ای واقعی** با React Router: خانه، درباره ما، محصولات (+ صفحه جزئیات هر محصول)،
  صادرات، کیفیت و گواهینامه‌ها، وبلاگ (+ صفحه هر مقاله)، تماس با ما و صفحه ۴۰۴
- **انیمیشن‌های فراوان و ظریف** با Framer Motion: ترنزیشن بین صفحات، Hero پارالاکس،
  نمایش پلکانی هنگام اسکرول، شمارنده‌های آماری متحرک، نوار شعار متحرک (Marquee)،
  منوی موبایل با افکت دایره‌ای، نوار پیشرفت اسکرول، افکت Ken Burns و دکمه‌های براق
- **هویت بصری Crimson/White** با تایپوگرافی فارسی **وزیرمتن** (Vazirmatn) و اعداد فارسی
- **شعار اصلی تبلیغاتی** «از مغز گندم؛ تا اولین برش نان» در Hero، نوار متحرک، بنر میانی و فوتر
- فیلتر برند‌ها (دزمایه، شتاب، ایکس پاور، نان مایه) با انیمیشن چیدمان
- فرم تماس با اعتبارسنجی و انیمیشن موفقیت
- **پنل مدیریت محتوا** در مسیر مخفی `/admin`: ویرایش متن/تصویر/پیوند همه صفحات،
  مدیریت محصولات و وبلاگ با ویرایشگر غنی (پیوند، عکس، ویدیو) و صندوق پیام‌های مردم
- **فروشگاه اینترنتی** با سبد خرید، قیمت ریالی، دیدگاه‌ها و پاسخ مدیر،
  مدیریت کامل سفارش‌ها و آماده اتصال به درگاه پرداخت ایرانی (زرین‌پال / آیدی‌پی)
  — **فقط روی نسخه فارسی سایت نمایش داده می‌شود**
- **سه‌زبانه (فارسی / انگلیسی / عربی)** با راست‌چین و چپ‌چین خودکار، سوییچر زبان در هدر و
  منوی موبایل، و ترجمه کامل همه محتوای شرکت (معرفی، مدیران، محصولات، مقالات و گواهینامه‌ها)
- **حالت تاریک (Dark Mode)** با پالت «قرمز لاکی + مشکی» و کلید تغییر در هدر؛ انتخاب کاربر ذخیره
  می‌شود و در نخستین بازدید از تنظیمات سیستم‌عامل پیروی می‌کند
- خروجی build بهینه + فایل `.htaccess` برای میزبانی SPA روی هاست‌های Apache/cPanel

## 🚀 اجرا و توسعه

```bash
npm install
npm run dev        # سرور توسعه (ویت پورت آزاد را خودش انتخاب می‌کند؛ معمولاً 5173)
npm run server     # سرور محتوا/API روی پورت 8787
npm run build      # خروجی تولید در پوشه dist
npm run preview    # پیش‌نمایش خروجی تولید
npm test           # build + مجموعه کامل تست (۸۶ بررسی)
```

> برای کار روی پنل مدیریت یا فروشگاه، `npm run dev` و `npm run server` باید هم‌زمان اجرا باشند؛
> ویت درخواست‌های `/api` و `/uploads` را به سرور Node پروکسی می‌کند.

## 🛠 پنل مدیریت محتوا (CMS)

نشانی پنل را **فقط با تایپ مستقیم در نوار آدرس** باز کنید — هیچ لینکی به آن در وب‌سایت وجود ندارد:

```
https://your-domain.com/admin
```

**در محیط توسعه** (روی کامپیوتر خودتان) نام کاربری `admin` و رمز `khyeast-1404` است.

⚠️ **این مقادیر فقط برای توسعه‌اند و در مخزن عمومی منتشر شده‌اند.** سرور در حالت
`NODE_ENV=production` عمداً **بالا نمی‌آید** تا `ADMIN_PASS` و `ADMIN_SECRET` واقعی تنظیم
نشوند — به **گام ۵** در راهنمای cPanel (پایین همین صفحه) مراجعه کنید.

متغیرهای محیطی قابل تنظیم: `ADMIN_USER`، `ADMIN_PASS`، `ADMIN_SECRET`، `PUBLIC_ORIGIN`،
`TRUSTED_HOSTS`، `PORT`، `DB_FILE`. نمونهٔ کامل در فایل `.env.example` آمده است؛ می‌توانید
آن را به `.env` کپی کنید (این فایل در `.gitignore` هست و هرگز commit نمی‌شود).

### امکانات پنل
- **محصولات**: ایجاد / ویرایش / حذف محصولات صفحه «محصولات» + بارگذاری تصویر + جدول مشخصات + راهنمای مصرف / آنالیز / نگهداری + انتخاب «برگزیده»
- **وبلاگ**: ایجاد / ویرایش / حذف مقالات + ویرایشگر متن غنی با **پیوند، تصویر و ویدیو** (بارگذاری فایل)
- **متون سایت**: ویرایش تک‌تک متن‌های همه صفحات (با جستجو و گروه‌بندی) — ذخیره خودکار
- **تصاویر صفحات**: جایگزینی تصویر هر بخش با بارگذاری فایل یا نشانی دلخواه
- **پیوندها**: تلفن‌ها، واتس‌اپ/تلگرام، دکمه‌های اصلی و پیوندهای داخلی
- **اطلاعات تماس**: دفترها/کارخانه‌ها (افزودن/حذف)، تلفن‌ها، نشانی‌ها، شبکه‌های اجتماعی هدر و فوتر، موضوعات فرم
- **پیام‌های مردم**: مشاهده پیام‌های فرم «ارسال پیام و استعلام قیمت»، علامت خوانده‌شده و حذف
- **ترجمه‌ها**: با انتخاب «English» یا «العربية» از کلید زبانِ بالای منوی کناری، تب «ترجمه‌ها» باز
  می‌شود؛ در آن، کنار هر ردیف **متن فارسی به‌عنوان مرجع** نمایش داده می‌شود و کادر ورودی، ترجمه
  فعلی سایت را به‌صورت placeholder نشان می‌دهد. هر کادری که خالی بماند، همان ترجمه پیش‌فرض
  را نگه می‌دارد؛ بنابراین هیچ‌گاه لازم نیست یک زبان از صفر وارد شود.
  بخش‌های قابل ترجمه: متون صفحات، فهرست‌ها (ویژگی‌ها، دفاتر، آمار، تایم‌لاین، گواهینامه‌ها…)،
  محصولات (عنوان، مشخصات، آنالیز، نگهداری)، مقالات (عنوان، چکیده و متن کامل) و برندها.

### امنیت محتوا
مدیر محتوا تنها «مقادیر محتوا» را تغییر می‌دهد؛ استایل و کد سایت غیرقابل دست‌کاری است:
- ویرایشگر متن غنی با **پاک‌ساز سخت‌گیرانه HTML** (`src/content/sanitize.jsx`): تگ‌های `script/style/iframe`، صفت‌های `style` و `class` و رویدادها حذف می‌شوند؛ فقط ساختار متن، `a[href]` با پروتکل‌های مجاز، `img` و `video` باقی می‌ماند.
- بارگذاری فقط برای تصاویر و ویدیو مجاز است؛ **نوع فایل از روی بایت‌های ابتدایی (magic number) بررسی می‌شود**، نه پسوند، و نام فایل سمت سرور بازتولید می‌گردد. فایل‌ها با هدرهای `nosniff` و CSP محدودکننده سرو می‌شوند تا حتی فایل دستکاری‌شده اجرا نشود. SVG عمداً پذیرفته نمی‌شود.
- دسترسی پنل با توکن امضاشده (HMAC) و انقضای ۱۲ ساعته.

## 🔐 امنیت

سایت چند دور تست نفوذ را پشت سر گذاشته است. آنچه در حال حاضر فعال است:

**احراز هویت**
- توکن امضاشده با HMAC-SHA256 و انقضای ۱۲ ساعته.
- **ابطال واقعی توکن**: هر توکن یک شناسه نشست دارد و تنها تا وقتی معتبر است که آن نشست
  سمت سرور ثبت باشد. «خروج از پنل» نشست را حذف می‌کند، پس هر نسخهٔ کپی‌شده از توکن هم
  بلافاصله باطل می‌شود. نشست‌ها در دیتابیس ذخیره می‌شوند تا ری‌استارت سرور کاربر را بیرون نیندازد.
- `POST /api/auth/logout-all` همهٔ نشست‌ها را باطل می‌کند (برای زمانی که توکنی لو رفته باشد).
- محدودیت نرخ روی ورود، فرم تماس، دیدگاه‌ها و ثبت سفارش.

**پیکربندی تولید**
سرور در حالت `NODE_ENV=production` **اجرا نمی‌شود** اگر:
- `ADMIN_PASS` یا `ADMIN_SECRET` هنوز مقدار پیش‌فرض باشند یا خیلی کوتاه باشند، یا
- نه `PUBLIC_ORIGIN` تنظیم شده باشد و نه `TRUSTED_HOSTS`.

دلیل دوم مهم است: نشانی بازگشت از درگاه پرداخت نباید از هدر `Host` درخواست ساخته شود،
وگرنه مهاجم می‌تواند آن را به دامنهٔ خودش منحرف کند و کد پیگیری سفارش را بدزدد.

**پرداخت**
- مبلغ پرداخت‌شده با مبلغ سفارش مقایسه می‌شود و در صورت **نبودن یا نامعتبر بودن مبلغ،
  پرداخت رد می‌شود** (fail closed) — نه اینکه بررسی نادیده گرفته شود.
- تمام مبالغ سمت سرور محاسبه می‌شوند؛ مقدار ارسالی از مرورگر هرگز مبنا نیست.
- کسر موجودی اتمیک است؛ دو خریدار هم‌زمان نمی‌توانند بیش از موجودی سفارش دهند.

**هدرهای امنیتی** (هم در سرور Node و هم در `.htaccess`)
`Content-Security-Policy`، `X-Content-Type-Options`، `X-Frame-Options`،
`Referrer-Policy`، `Permissions-Policy`، `Cross-Origin-Opener-Policy` و در تولید روی
HTTPS، `Strict-Transport-Security`.

> در سرور Node، مقدار `script-src` به‌جای `unsafe-inline` از **هش sha256** اسکریپت
> درون‌خطی استفاده می‌کند و این هش هنگام راه‌اندازی از روی فایل build محاسبه می‌شود.

**سایر موارد**
- خطاها هرگز stack trace یا مسیر فایل‌های سرور را برنمی‌گردانند.
- تمام کوئری‌ها پارامتری هستند (بدون امکان SQL Injection).
- اعتبارنامهٔ درگاه پرداخت هرگز در API عمومی منتشر نمی‌شود.
- `npm audit` بدون آسیب‌پذیری.

**آنچه هنوز باز است:** سقفی برای تعداد یا حجم کل فایل‌های بارگذاری‌شده وجود ندارد
(هر فایل حداکثر ۲۰۰ مگابایت، و فقط برای مدیر واردشده).

### اجرای سرور محتوا
پنل و ذخیره‌سازی محتوا به سرور Node نیاز دارد:

```bash
npm run server     # API + آپلودها روی پورت 8787
npm run dev        # در توسعه، ویت درخواست‌های /api و /uploads را پروکسی می‌کند
npm run build      # در تولید، همان سرور Node پوشه dist را نیز سرو می‌کند
```

## 🗄 دیتابیس

ذخیره‌سازی داده‌های زمان اجرا روی **SQLite** انجام می‌شود: یک فایل تکی و تراکنشی، بدون نیاز
به نصب سرویس دیتابیس جداگانه.

درایور پیش‌فرض ماژول **داخلی `node:sqlite`** (نود ۲۲ به بالا) است، بنابراین سایت روی هاست
اشتراکی بدون نیاز به کامپایلر بالا می‌آید. اگر `better-sqlite3` نصب شده باشد، به‌صورت خودکار
از آن (سریع‌تر) استفاده می‌شود — ولی نصبش الزامی نیست و در وابستگی‌های پروژه نیامده است.

| محل ذخیره | داده |
| --- | --- |
| `server/data/khyeast.db` | محصولات فروشگاه، تنظیمات فروشگاه، اعتبارنامه درگاه پرداخت، سفارش‌ها و اقلام آن‌ها، دیدگاه‌ها، پیام‌های تماس |
| `server/data/content.json` | متن‌ها، تصاویر، پیوندها، برندها، محصولات کاتالوگ و مقالات وبلاگ (ویرایش تک‌کاربره از پنل) |
| `server/uploads/` | فایل‌های بارگذاری‌شده مدیر |

**جدول‌ها:** `settings`، `products`، `orders`، `order_items`، `comments`، `messages`.

**چرا SQLite:** حالت WAL و تراکنش‌ها نوشتن هم‌زمان را ایمن می‌کنند — مثلاً کسر موجودی
هنگام ثبت سفارش به‌صورت اتمیک انجام می‌شود و دو خریدار هم‌زمان نمی‌توانند بیش از موجودی
سفارش دهند. ایندکس‌ها روی `orders.at`، `orders.status`، `comments.slug` و `messages.at`
گزارش‌گیری پنل را سریع نگه می‌دارند. حذف سفارش با `ON DELETE CASCADE` اقلام آن را هم پاک می‌کند.

**مهاجرت خودکار:** در نخستین اجرا، اگر فایل‌های قدیمی `shop.json` و `messages.json` و بخش
`shop` داخل `content.json` موجود باشند، محتوایشان یک‌بار به دیتابیس منتقل می‌شود و پس از آن
دیتابیس تنها منبع حقیقت این داده‌هاست (لاگ راه‌اندازی گزارش تعداد رکوردهای منتقل‌شده را نشان می‌دهد).

**پشتیبان‌گیری:** کافی است `server/data/` و `server/uploads/` را کپی کنید. برای بکاپ گرم
می‌توانید از `sqlite3 server/data/khyeast.db ".backup backup.db"` استفاده کنید.

**مسیر دیتابیس** با متغیر محیطی `DB_FILE` قابل تغییر است.

⚠️ دیتابیس روی دیسک ماندگار نیاز دارد؛ روی سرویس‌های serverless بدون دیسک دائمی (مانند اجرای
بدون volume) داده‌ها حفظ نمی‌شوند — یک VPS یا هاست با دیسک ماندگار استفاده کنید.

## 🛒 فروشگاه اینترنتی

صفحه فروشگاه در نشانی `/shop` (از منوی اصلی و فوتر در دسترس است):

- **کارت محصولات** با قیمت ریالی، نشان تخفیف/برگزیده و وضعیت موجودی
- **صفحه محصول** با مشخصات، توضیحات غنی، پیوند به کاتالوگ فنی و محصولات مرتبط
- **سبد خرید** (`/shop/cart`) با کنترل تعداد و محاسبه ارسال رایگان
- **پرداخت** (`/shop/checkout`) با اعتبارسنجی کامل؛ مبالغ **همیشه سمت سرور** محاسبه می‌شوند
- **پیگیری سفارش** (`/shop/order/<code>`) با تایم‌لاین وضعیت و کد پیگیری خصوصی
- **دیدگاه‌ها و پرسش‌ها** زیر هر محصول + پاسخ مدیر + امکان تأیید پیش از نمایش و قفل بخش دیدگاه‌ها

### مدیریت فروشگاه از پنل (`/admin`)
| تب | کارکرد |
| --- | ------ |
| فروشگاه — محصولات | افزودن/حذف محصول، قیمت (ریال) و قیمت تخفیف، موجودی، تصویر، توضیحات غنی، جدول مشخصات، فعال/غیرفعال، **قفل دیدگاه‌های هر محصول** + تنظیمات واحد نمایش (ریال/تومان)، هزینه و سقف ارسال رایگان |
| سفارش‌ها | مشاهده اقلام/مشتری/مبالغ، تغییر وضعیت (در انتظار پرداخت ← پرداخت‌شده ← ارسال ← تحویل / لغو)، یادداشت داخلی، حذف |
| دیدگاه‌ها | تأیید/رد، **پاسخ به دیدگاه‌ها**، حذف |
| درگاه پرداخت | فعال‌سازی **زرین‌پال** یا **آیدی‌پی** با وارد کردن Merchant ID / API Key — بدون تغییر کد |

### اتصال به درگاه پرداخت ایرانی
مبالغ فروشگاه به **ریال** ذخیره و هنگام ارسال به درگاه به‌صورت خودکار به **تومان** تبدیل می‌شوند.
اعتبارنامه درگاه فقط در دیتابیس سمت سرور (`server/data/khyeast.db`، جدول `settings`) نگهداری می‌شود و هرگز در API عمومی منتشر نمی‌شود.

- **زرین‌پال**: در تب «درگاه پرداخت» Merchant ID را وارد کنید (شناسه‌های `test-*` به محیط sandbox می‌روند).
  پرداخت از `api.zarinpal.com/pg/v4` و بازگشت از `/api/shop-pay/zarinpal/callback` انجام می‌شود.
- **آیدی‌پی**: API Key را وارد کنید و در صورت نیاز حالت Sandbox را فعال نگه دارید.
- تا فعال‌نشدن درگاه، سفارش‌ها با وضعیت «در انتظار پرداخت» ثبت و از پنل مدیریت می‌شوند.
- اگر سایت پشت پروکسی/دامنه دیگری است، «نشانی پایه بازگشت از درگاه» را روی دامنه نهایی تنظیم کنید.

## ⚡ بهینه‌سازی برای اینترنت کند

سایت برای کاربرانی که سرعت پایین یا اینترنت موبایل دارند بهینه شده است:

**۱. تقسیم کد بر اساس صفحه (code splitting)**
هر صفحه چانک جداگانه خودش را دارد؛ بازدیدکننده فقط همان صفحه‌ای را دانلود می‌کند که خواسته است.
جاوااسکریپت مسیر بحرانی حدود **۱۴۷ کیلوبایت فشرده** است (اسکلت ۳۰ + React‏ ۵۵ + انیمیشن ۴۷ + مسیریاب ۱۴).

**۲. پیش‌واکشی هوشمند چانک‌ها** (`src/routes.js`)
کد اسپلیتینگ به‌تنهایی ناوبری را کندتر می‌کند، پس چانک‌ها از قبل گرم می‌شوند:
- در زمان بیکاری مرورگر (`requestIdleCallback`)، صفحات پربازدید
- با **هاور/لمس/فوکوس** روی هر لینک داخلی — ۱۰۰ تا ۳۰۰ میلی‌ثانیه جلوتر از کلیک
- همسایه‌های صفحه فعلی (مثلاً از سبد خرید → تسویه حساب)

کاربران با **۲G یا حالت Data Saver** از پیش‌واکشی معاف می‌شوند تا حجم مصرفی‌شان هدر نرود.

**۳. فشرده‌سازی gzip روی سرور**
میان‌افزار `compression` روی Express؛ برای هاست‌های Apache همین تنظیمات (و Brotli در صورت
پشتیبانی) در `public/.htaccess` آمده است.

**۴. کش‌کردن محتوا در مرورگر (stale-while-revalidate)**
`ContentContext` آخرین نسخه `/api/content` را در localStorage نگه می‌دارد؛ بازدید دوم
بدون انتظار برای شبکه رندر می‌شود و نسخه تازه در پس‌زمینه جایگزین می‌گردد.

**۵. لودینگ هوشمند به‌جای تأخیر ثابت** (`src/hooks/useLoadingGate.js`)
نمایش اسکلت صفحه بر اساس **کیفیت واقعی اتصال** زمان‌بندی می‌شود، نه یک عدد ثابت:
روی اتصال سریع دیرتر (تا ۴۰۰ms) ظاهر می‌شود تا برای بارگذاری‌های آنی اصلاً دیده نشود،
و روی ۲G/۳G زودتر (۶۰ تا ۱۴۰ms) تا کاربر صفحهٔ ساکن نبیند. وقتی ظاهر شد، دست‌کم
۳۲۰ میلی‌ثانیه می‌ماند تا پرش ایجاد نکند.

**۶. انیمیشن سبک‌تر و یکدست**
۶۳ انیمیشن ظاهرشدن هنگام اسکرول از Framer Motion به یک **IntersectionObserver مشترک** با
ترنزیشن‌های CSS منتقل شدند که فقط `transform` و `opacity` را تغییر می‌دهند (بدون layout).
حالت `AnimatePresence` روی `popLayout` است تا صفحهٔ جدید منتظر خروج صفحهٔ قبلی نماند،
و وضعیت اسکرول هدر با `requestAnimationFrame` throttle می‌شود.
کاربران با `prefers-reduced-motion` فقط یک فید کوتاه می‌بینند.

> این مسیر **برای همه یکسان** است و به مشخصات دستگاه (حافظه، تعداد هسته) وابسته نیست.

**۷. کش‌گذاری و preload**
فایل‌های هش‌دار با `max-age=31536000, immutable` و `index.html` با `no-cache` سرو می‌شوند.
`/api/content` و تصویر هیرو در `<head>` preload می‌شوند تا قبل از پارس‌شدن باندل شروع شوند.

**۸. تصاویر WebP**
تصاویر سایت به WebP تبدیل شده‌اند: مجموعاً از ۵۵۰۴ به ۸۱۶ کیلوبایت (**۸۵٪ کاهش**) بدون
افت محسوس کیفیت. اسکریپت `scripts/to-webp.mjs`.

## 🖼 درباره تصاویر محصولات

تصاویر بسته‌بندی، رندرهای استودیویی با لیبل‌های طراحی‌شده برند (نشان گندم + پالت
Crimson/White) هستند که با اسکریپت `scripts/rebrand-packs.mjs` یکدست‌سازی شده‌اند.
برای جایگزینی با عکس‌های واقعی محصولات، کافی است فایل‌های هم‌نام در
`public/assets/products/` را جایگزین کنید — یا ساده‌تر، از **تب «محصولات» پنل مدیریت**
تصویر هر محصول را بارگذاری کنید (نیازی به دسترسی به کد نیست).

سایت فقط نسخهٔ `.webp` تصاویر را سرو می‌کند (هر کدام حدود ۴۰ کیلوبایت به‌جای

می‌شود؛ این پوشه عمداً بیرون از `public/` است تا در خروجی build و در آپلود روی
هاست نیاید. اگر تصویری را عوض کردید، با دستور `node scripts/to-webp.mjs`
نسخهٔ webp را دوباره بسازید.

لوگوی رسمی شرکت در `public/assets/brand/logo.png` است و در هدر، فوتر، پنل و صفحهٔ
بارگذاری استفاده می‌شود.

## حالت A — انتشار استاتیک (ساده)

### گام ۲ — فشرده کردن خروجی

**محتویات داخل** پوشهٔ `dist` را انتخاب کنید (نه خود پوشه را) و یک فایل ZIP بسازید.

- ویندوز: همه را انتخاب → راست‌کلیک → Send to → Compressed (zipped) folder
- مک: همه را انتخاب → راست‌کلیک → Compress

### گام ۳ — آپلود

1. وارد cPanel شوید.
2. **File Manager** را باز کنید.
3. وارد پوشهٔ **`public_html`** شوید.
4. اگر فایل پیش‌فرض هاست (مثل `default.html`) آنجاست، حذفش کنید.
5. دکمهٔ **Upload** → فایل ZIP را انتخاب کنید.
6. پس از پایان آپلود، به File Manager برگردید، روی فایل ZIP راست‌کلیک کنید → **Extract**.
7. فایل ZIP را پس از استخراج حذف کنید.

### گام ۴ — بررسی فایل مخفی `.htaccess`

در File Manager روی **Settings** (گوشهٔ بالا-راست) کلیک کنید و تیک
**Show Hidden Files (dotfiles)** را بزنید.

حالا باید `.htaccess` را کنار `index.html` ببینید. اگر **نبود**، آن را دستی بسازید:
**+ File** → نام: `.htaccess` → سپس محتوای فایل `public/.htaccess` پروژه را داخلش کپی کنید.

### گام ۵ — فعال کردن HTTPS

در cPanel → بخش **Security** → **SSL/TLS Status** → دکمهٔ **Run AutoSSL**.
چند دقیقه بعد سایت با `https://` باز می‌شود.

✅ سایت شما بالاست. آدرس دامنه را در مرورگر باز کنید.

## حالت B — انتشار کامل با Node.js (پنل مدیریت + فروشگاه)

### گام ۲ — آماده کردن فایل‌ها

کل پروژه را آپلود می‌کنید، نه فقط `dist`. اما این‌ها را **آپلود نکنید**:

- پوشهٔ `node_modules` (حجیم است؛ روی سرور دوباره نصب می‌شود)
- پوشهٔ `.git`
- پوشهٔ `assets-src` (نسخهٔ اصلی تصاویر، حدود ۵ مگابایت؛ سایت از آن استفاده نمی‌کند)
- فایل `.env` اگر ساخته‌اید (رمزها را جداگانه وارد می‌کنیم)

ساده‌ترین راه: از پروژه یک ZIP بگیرید و سه مورد بالا را از داخلش حذف کنید.

> حتماً `npm run build` را قبلش زده باشید تا پوشهٔ `dist` داخل ZIP باشد. سرور Node همین
> پوشه را به بازدیدکننده‌ها نشان می‌دهد.

### گام ۳ — ساختن پوشه روی سرور

1. File Manager → وارد پوشهٔ **`home`** خود شوید (یک سطح بالاتر از `public_html`).
2. **+ Folder** → نامش را بگذارید `khyeast-app`.
3. واردش شوید و ZIP را آپلود و **Extract** کنید.

> **چرا بیرون از `public_html`؟** چون هر چیزی داخل `public_html` باشد مستقیماً از اینترنت
> قابل دانلود است — از جمله فایل دیتابیس و رمزها. کد برنامه باید بیرون از آن بماند.

### گام ۴ — ساختن اپلیکیشن Node

1. cPanel → بخش **Software** → **Setup Node.js App**.
2. **Create Application** را بزنید و این مقادیر را وارد کنید:

| فیلد | مقدار |
| --- | --- |
| Node.js version | بالاترین نسخهٔ موجود (**حداقل ۲۲**) |
| Application mode | **Production** |
| Application root | `khyeast-app` |
| Application URL | دامنهٔ خودتان |
| Application startup file | `server/index.js` |

3. **Create** را بزنید.

> اگر بالاترین نسخهٔ Node موجود کمتر از ۲۲ بود، از پشتیبانی هاست بخواهید نسخهٔ ۲۲ را
> فعال کند. دیتابیس به ماژول داخلی `node:sqlite` نیاز دارد که از نسخهٔ ۲۲ در دسترس است.

### گام ۵ — وارد کردن رمزها (مهم‌ترین گام امنیتی)

⚠️ **سرور در حالت Production عمداً بالا نمی‌آید تا این مقادیر را تنظیم نکنید.** این یک
محافظ است، نه خطا — رمز پیش‌فرض در مخزن عمومی منتشر شده و هر کسی می‌تواند با آن وارد
پنل شود.

ابتدا یک کلید امنیتی تصادفی بسازید. روی کامپیوتر خودتان اجرا کنید:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

یک رشتهٔ ۶۴ کاراکتری می‌دهد. کپی‌اش کنید.

حالا در همان صفحهٔ **Setup Node.js App**، بخش **Environment variables** را باز کنید و
با دکمهٔ **Add Variable** این‌ها را یکی‌یکی اضافه کنید:

| نام متغیر | مقدار |
| --- | --- |
| `NODE_ENV` | `production` |
| `ADMIN_USER` | نام کاربری دلخواه شما |
| `ADMIN_PASS` | رمز قوی خودتان (**حداقل ۱۲ کاراکتر**) |
| `ADMIN_SECRET` | همان رشتهٔ ۶۴ کاراکتری که ساختید |
| `PUBLIC_ORIGIN` | `https://your-domain.com` (دامنهٔ واقعی خودتان) |

> `PUBLIC_ORIGIN` را حتماً با `https://` و **بدون اسلش انتهایی** بنویسید. نشانی بازگشت از
> درگاه پرداخت از روی همین ساخته می‌شود؛ اگر اشتباه باشد، پرداخت به سایت شما برنمی‌گردد.

### گام ۶ — نصب وابستگی‌ها و اجرا

1. در همان صفحه، دکمهٔ **Run NPM Install** را بزنید و منتظر بمانید (۱ تا ۳ دقیقه).
2. سپس **Restart** را بزنید.
3. دامنه را در مرورگر باز کنید.

### گام ۷ — اگر سایت بالا نیامد

در صفحهٔ Setup Node.js App لینک لاگ‌ها را باز کنید. پیام‌های رایج:

| پیام در لاگ | معنی و راه‌حل |
| --- | --- |
| `REFUSING TO START — insecure configuration` | یکی از متغیرهای گام ۵ تنظیم نشده یا رمز کوتاه است. لاگ دقیقاً می‌گوید کدام مورد ایراد دارد. |
| `Cannot find module` | دکمهٔ **Run NPM Install** را نزده‌اید. |
| `EADDRINUSE` | پورت اشغال است؛ فقط **Restart** بزنید. متغیر `PORT` را دستی تنظیم نکنید — cPanel خودش آن را می‌دهد. |
| صفحهٔ سفید | `npm run build` را قبل از آپلود نزده‌اید، پس پوشهٔ `dist` وجود ندارد. |

### گام ۸ — ورود به پنل مدیریت

نشانی پنل **هیچ لینکی در سایت ندارد** و باید مستقیم در نوار آدرس تایپ شود:

```
https://your-domain.com/admin
```

با `ADMIN_USER` و `ADMIN_PASS` که در گام ۵ تعیین کردید وارد شوید.

### پس از راه‌اندازی

**۱. پشتیبان‌گیری — این مهم‌ترین کار بعد از انتشار است.**

تمام محتوای سایت، سفارش‌ها و پیام‌ها در دو جا هستند:

```
khyeast-app/server/data/      ← دیتابیس و محتوای سایت
khyeast-app/server/uploads/   ← تصاویر و ویدیوهای بارگذاری‌شده
```

هر چند وقت یک‌بار از این دو پوشه در File Manager یک ZIP بگیرید و دانلود کنید.

⚠️ **هنگام به‌روزرسانی سایت، این دو پوشه را هرگز پاک نکنید.** محتوایی که از پنل وارد
کرده‌اید آنجاست، نه در کد.

**۲. فعال کردن درگاه پرداخت**

وارد پنل شوید → تب **درگاه پرداخت** → Merchant ID زرین‌پال یا API Key آیدی‌پی را وارد کنید.
نیازی به تغییر کد نیست. تا وقتی درگاه فعال نشده، سفارش‌ها با وضعیت «در انتظار پرداخت» ثبت
می‌شوند و می‌توانید دستی مدیریتشان کنید.

**۳. به‌روزرسانی سایت در آینده**

```bash
npm run build
```

سپس فقط پوشهٔ `dist` را روی سرور جایگزین کنید و در Setup Node.js App دکمهٔ **Restart** را
بزنید. پوشه‌های `server/data` و `server/uploads` دست‌نخورده می‌مانند.

## 🌐 چندزبانگی (فارسی / انگلیسی / عربی)

### نشانی‌ها
| زبان | مسیر | جهت | فونت |
| --- | --- | --- | --- |
| فارسی (پیش‌فرض) | `/`، `/products`، `/blog/…` | RTL | Vazirmatn |
| English | `/en`، `/en/products`، `/en/blog/…` | LTR | Inter |
| العربية | `/ar`، `/ar/products`، `/ar/blog/…` | RTL | Vazirmatn |

نسخه فارسی **بدون پیشوند** در ریشه سایت می‌ماند، بنابراین تمام نشانی‌های قبلی دست‌نخورده
کار می‌کنند. پیشوند `/en` و `/ar` به‌صورت `basename` به React Router داده می‌شود؛ به همین
دلیل هیچ‌کدام از لینک‌های داخلی صفحات نیاز به تغییر نداشتند.

### معماری ترجمه
محتوای فارسی **پایه** است و همیشه کامل؛ انگلیسی و عربی «لایه روکش» هستند:

```
shared/contentDefaults.js      ← فارسی (پایه، همیشه کامل)
        ↓ روکش ۱
shared/i18n/en.js | ar.js      ← دیکشنری ارائه‌شده با پروژه
        ↓ روکش ۲
state.i18n[locale]             ← ترجمه‌های ویرایش‌شده در پنل مدیریت
```

هر کلیدی که ترجمه نشده باشد، به‌جای ناپدید شدن، نسخه فارسی خود را نمایش می‌دهد.
دیکشنری هر زبان یک **چانک جداگانه** است؛ بازدیدکننده فارسی هیچ‌گاه فایل انگلیسی یا
عربی را دانلود نمی‌کند.

### فروشگاه
فروشگاه اینترنتی یک سرویس داخلی (ریال + درگاه پرداخت ایرانی) است، بنابراین تب «فروشگاه»،
آیکن سبد خرید و مسیرهای `/shop/*` **تنها روی نسخه فارسی** فعال هستند. اگر کاربر هنگام حضور
در صفحات فروشگاه زبان را عوض کند، به صفحه اصلی همان زبان هدایت می‌شود.

### سئو
در هر تغییر مسیر، `title`، `description`، `og:locale`، `canonical` و تگ‌های
`hreflang` (شامل `x-default`) برای هر سه زبان به‌صورت خودکار به‌روزرسانی می‌شوند.
